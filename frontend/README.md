# Сканер российских вин

Интерфейс на Nuxt 4 + TypeScript. Основной язык — русский. Backend находится в корне этого репозитория; по умолчанию без локальной настройки включено явно обозначенное демо.

## Запуск

Нужен Node.js **22.22+** (проверено 22.22.2) и npm.

```sh
cd wine-scanner/frontend
npm ci
npm run dev
```

Открыть http://localhost:3000. Зависимости зафиксированы в `package-lock.json`. Демо-файлы уже подготовлены, Python и исходный архив для обычного запуска не нужны. Внешние шрифты и CDN приложение не использует.

Проверки и production:

```sh
npm test
npm run typecheck
npm run build
npm run preview
```

`preview` запускает собранный Node-сервер на порту 3000. При необходимости задайте `PORT=3001 npm run preview`. Не запускайте dev и preview на одном порту одновременно.

## Подключение API

```sh
NUXT_PUBLIC_RECOGNITION_MODE=api \
NUXT_PUBLIC_API_BASE=http://127.0.0.1:8112 \
npm run dev
```

Для текущего GPU-сервера сначала откройте на Mac туннель `ssh -N -L 127.0.0.1:8112:127.0.0.1:8110 GPU_8_A100`. Оба процесса backend должны работать на GPU2; проверка: `curl http://127.0.0.1:8112/health/ready`. На VPS frontend использует пустой `NUXT_PUBLIC_API_BASE` и проксирует `/v1/*` и `/health/*` на локальный `127.0.0.1:8110`; этому адресу нужен SSH-туннель VPS → GPU-сервер. Если туннель или backend остановится, интерфейс покажет ошибку соединения.

Либо скопировать `.env.example` в `.env`, изменить значения и перезапустить dev. В production переменные нужно передать процессу `npm run preview`: `.env` там автоматически не читается. Адрес публичный, секреты в нём хранить нельзя. Пустой `API_BASE` означает тот же origin, что у интерфейса; для этого потребуется маршрутизация `/v1/*` и `/health/*` в backend.

Переключатель «Настройки демо / API» позволяет явно сменить режим. При смене фото и результат сбрасываются; автоматического перехода с API на демо нет. Демонстрационный сценарий никогда не влияет на реальный запрос.

Подключённый сервис поддерживает:

- `GET /health/ready`: HTTP 2xx означает готовность, тело не требуется.
- `POST /v1/recognize`: `multipart/form-data`, поле `image`.
- `GET /v1/wines/{slug}`: нормализованная карточка.

Подробности, формат JSON и дополнения к контракту — в [API_CONTRACT.md](API_CONTRACT.md). API и DTO вынесены в `app/services/`. При VPS-прокси запросы остаются на origin интерфейса, поэтому браузеру не нужен прямой доступ к GPU-серверу. Текущий backend всегда возвращает лучший slug; при `low_confidence: true` интерфейс не показывает этот неподтверждённый кандидат и не запрашивает его карточку. Порог флага задаётся на backend (`WS_LOW_CONFIDENCE`, по умолчанию 0,3). Его `confidence` — оценка верификатора, а не вероятность правильного распознавания, поэтому процент на экране не показывается. Credentials к API не отправляются.

Изображение найденной карточки браузер загружает по внешнему HTTPS `image_url` из каталога (`api.vino-svoe.ru`). Это отдельная загрузка после ответа API. Для карточек без изображения отображается заглушка; фото пользователя остаётся в предпросмотре и не подменяет фото каталога.

Клиент отменяет предыдущий запрос через AbortController и проверяет номер операции после асинхронных шагов. Поздний ответ не может заменить новый снимок. Общий таймаут готовности/распознавания/карточки — 20 секунд, альтернатив — 15 секунд. Ошибка альтернатив не скрывает найденное вино.

## Фотографии и камера

Поддерживаются JPEG, PNG, WebP до 15 МиБ и 30 Мп. Проверяются MIME, размер и возможность декодирования. HEIC отклоняется с просьбой сохранить JPEG. Сервис обязан повторять проверки самостоятельно. Никаких ответов по имени, хешу или порядку файла нет.

«Сфотографировать» открывает встроенную камеру (`getUserMedia`, по возможности заднюю). Можно сделать JPEG-кадр или закрыть окно, в том числе Escape. Поток останавливается после снимка/закрытия/ухода со страницы; позднее разрешение доступа тоже не оставляет включённую камеру. При отказе показана подсказка и доступен выбор файла.

Камера требует **HTTPS либо localhost** и разрешения браузера/ОС. Для телефона обычный HTTP по LAN позволяет выбирать фото, но браузер может запретить поток камеры. Для съёмки на телефоне потребуется доверенный локальный HTTPS. В демо выбранное фото не отправляется на сервер: только локальный blob preview, без localStorage. В API-режиме фото передаётся настроенному сервису; его политика хранения согласуется отдельно.

## Демо за 2–3 минуты

1. Оставить «Демонстрационный режим». Нажать «Попробовать на примере» либо выбрать любое фото.
2. Показать предпросмотр; заменить фото при желании. Нажать «Показать демо-результат».
3. Открывается **Cru Lermont Chardonnay, Фанагория**. Народный рейтинг есть, оценка гида не указана. Ни одно значение не дополнено догадкой.
4. Прокрутить «К чему подать» и «Чем заменить». Причины выбора альтернатив основаны на совпадающих категории, сортах и гастросочетаниях.
5. В настройках выбрать «Найдено · две оценки», повторно отправить фото: **Шардоне, Усадьба Маркотх**, отдельные 5 и 4,33.
6. Выбрать «Неполная карточка»: отсутствующие сведения остаются отсутствующими.
7. Показать один сценарий пересъёмки, «Нет надёжного совпадения» и ошибку соединения. Повторная отправка доступна; сценарий остаётся фиксированным, пока ведущий явно не изменит его.
8. Нажать «Новое сканирование».

Демо не является оценкой качества модели. Оно имитирует только пользовательский путь, длительность обработки фиксирована (1,4 с). Сценарий не определяется по фото. Автоматический набор альтернатив работает только после успешной карточки; при неизвестном вине произвольные аналоги не предлагаются.

## Данные

Всего 5 карточек и 5 исходных изображений (345 738 байт суммарно). `public/demo/cards.json` загружается по запросу, полный каталог не включён ни в JS, ни в public. Исходный uploads целиком не копируется.

Воспроизведение из имеющихся материалов проекта:

```sh
npm run demo:data
```

Скрипт на стандартном Python 3 выбирает явно перечисленные slug из `../data/catalog_v1/catalog.jsonl`, копирует только их изображения, сохраняет реальные nullable-поля и манифест с SHA-256 (`scripts/demo-manifest.json`). Slug не переименовываются. `similar_wine_slugs` ограничены доступным демо-набором. В демо добавлены объяснимые альтернативы по точному совпадению полей; в API — до трёх карточек из `similar_wine_slugs`, без подмены демо-данными.

Стилистический референс: https://vino-svoe.ru/wines — тёплый светлый фон, бордовый акцент, заголовки с засечками, крупные фотографии вина. Иллюстрация первого экрана собрана в CSS вокруг реальной бутылки из каталога.

## Проверки и ограничения

См. [VERIFICATION.md](VERIFICATION.md). Пройдены сборка, типы и автоматические сценарии; интерфейс просмотрен в браузере на настольной и мобильной ширине. На реальном телефоне ещё нужно проверить физический захват камеры, системные разрешения и EXIF-ориентацию. Встроенный браузер среды не предоставил реальный видеопоток: захват и освобождение камеры проверены с подставным MediaStream в тестах.

Оставшиеся интеграционные задачи:

1. Обеспечить автоматический перезапуск GPU2 backend и SSH-туннеля VPS → GPU-сервер после перезагрузки или обрыва сети. Для проверки цепочки использовать `/health/ready` через frontend, затем отправку тестового фото.
2. Проверить поведение ссылок `image_url` на всех устройствах и при недоступности `api.vino-svoe.ru`; часть карточек не содержит изображение.
3. Уточнить исходный каталог, шкалу «Оценки гида» и неоднозначные этикетки по `QUESTIONS_FOR_ORGANIZERS.md`.
4. Проверить съёмку в iOS Safari / Android Chrome, EXIF и допустимый размер фотографий на устройствах демонстрации.
5. Уточнить хранение загруженных фото и авторизацию, если они появятся.
