# Дополнения frontend к предварительному продуктовому API

Первоначально описан 16.09.2026. Проверен 29.09.2026 против [wine-scanner](https://github.com/Patrik1352/wine-scanner) (коммит `d0e447c`). `DESIGN.md` и общие исходные файлы не изменены.

## Распознавание

Сохранены `POST /v1/recognize`, multipart-поле `image`, и три статуса:

```json
{"status":"matched","slug":"fanagoriya-cru-lermont-chardonnay-shardone-beloe-suhoe-14"}
```

```json
{"status":"needs_better_photo","slug":null,"reason_code":"multiple_bottles"}
```

```json
{"status":"no_confident_match","slug":null,"reason_code":"low_match_score"}
```

`matched` требует непустой slug. Два других статуса требуют `slug: null` и непустой `reason_code`. Противоречивый ответ считается ошибкой сервиса. Текущий backend всегда возвращает `matched` с лучшим кандидатом каталога. При `low_confidence: true` интерфейс считает этот кандидат неподтверждённым, не запрашивает его карточку и показывает экран без совпадения. Порог флага задаёт backend через `WS_LOW_CONFIDENCE` (по умолчанию 0,3); фронтенд не дублирует числовой порог. `confidence` в этом backend — P(YES) верификатора, не откалиброванная вероятность правильного ответа; интерфейс не показывает её процентом. `top_k`, версии и timings также не занимают основной экран.

Подсказки: `multiple_bottles`, `low_quality`, `ambiguous_pair`, `low_match_score` — из DESIGN; дополнительно поддержаны `blurry`, `glare`, `too_dark`. Для неизвестного кода — нейтральная просьба снять этикетку крупнее/контрэтикетку. Добавленные коды не обязательны для backend.

HTTP 400/415/422 — изображение не прочитано; 413 — превышен размер; 503 и другие ошибки — недоступность сервиса. Ошибка соединения, таймаут, невалидный JSON и неверная схема не преобразуются в `no_confident_match`. Для readiness ожидается 2xx (включая 204), тело не проверяется; любой иной статус не даёт отправить фото.

## Карточка — уточнение отсутствовавшей схемы

`GET /v1/wines/{slug}` возвращает непосредственно объект, без обёртки `data`/`wine`. Минимально обязательны `slug`, `name`. Ответ должен иметь ровно запрошенный slug. Необязательные значения могут отсутствовать или быть null; списки нормализуются в `[]`.

```json
{
  "slug": "usadba-markoth-shardone-beloe-suhoe-12",
  "name": "Шардоне",
  "winery_name": "Усадьба Маркотх",
  "region": "Кубань",
  "category": "Белое сухое",
  "color_category": "Белое",
  "sweetness_from_category": "сухое",
  "grapes": ["Шардоне"],
  "description": null,
  "alcohol_percent": 12,
  "alcohol_max_percent": null,
  "serving_temperature_c": "8–12",
  "food_pairings": ["Блюда из птицы", "Рыба и морепродукты", "Салаты", "Средиземноморская кухня"],
  "public_rating": 5,
  "guide_rating": 4.33,
  "image_url": "/images/wine.webp",
  "source_url": "https://vino-svoe.ru/wines/usadba-markoth-shardone-beloe-suhoe-12",
  "fetched_at": "2026-09-15T09:11:45.851127+00:00",
  "similar_wine_slugs": ["znoj-denisov-vajneri", "cantiani-riesling-rkatsiteli"]
}
```

Названия полей совпадают с нормализованным каталогом. В примере `description: null` показывает допустимый пропуск, а `image_url` — пример пути API, не утверждение о существующем endpoint изображений.

Числа передаются числами (не строками). Крепость показывается диапазоном при `alcohol_max_percent != null`; температура остаётся строкой, единица °C добавляется интерфейсом. Шкала оценок не предполагается и не пересчитывается. Поле `guide_rating` называется только «Оценка гида».

`image_url` — HTTP(S) URL или относительный URL к API. Локальные пути файлов из `image_local_path` сервер обязан преобразовать в доступные URL. При отсутствующем/сломавшемся изображении выводится заглушка. Небезопасные протоколы ссылок отбрасываются. HTML из описания не исполняется.

Текущий backend передаёт исходный HTTPS `image_url` каталога (`api.vino-svoe.ru`), а не файл эталона и не картинку из загруженного фото. Браузер запрашивает этот URL отдельно; у части карточек изображения нет.

## Альтернативы

Новый endpoint не введён. После успешного совпадения UI берёт до трёх уникальных `similar_wine_slugs` (без текущего slug) и получает карточки через существующий GET. Объяснения строятся на точных совпадениях категории, сортов и блюд. Если общих полей нет, источник прямо обозначается: «по рекомендации каталога». Сам frontend не утверждает сходство вкуса, цены, наличия, урожая или качества. Ошибка загрузки альтернатив отображается отдельно с повтором, основная карточка остаётся доступной.

В демо сравнение идёт по пяти карточкам, для отсутствующих данных выводится явный пропуск. Полный каталог никогда не запрашивается клиентом.
