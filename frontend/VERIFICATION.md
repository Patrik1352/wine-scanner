# Проверка интерфейса

Обновлено 29.09.2026, Nuxt 4.5.2. Команды выполняются из `frontend/`.

- `npm run typecheck` — успешно.
- `npm run build` — успешно, SSR/Node output. Production-сервер на порту 3001 проверен в браузере: пример → предпросмотр → обработка → карточка → гастросочетания/альтернативы, ошибок console нет.
- `npm test` — 27 тестов: схема JSON, nullable-поля, две оценки, multipart, URL, неверный slug, невалидный JSON, HTTP/сеть, явные демо-сценарии, объяснения альтернатив, MIME/пустой/большой/повреждённый файл, 30 Мп, отказ камеры, JPEG-кадр, остановка и поздний stream, устаревший ответ, смена режима, retry, ошибка альтернатив, таймаут. В том числе ответ API `matched` с `low_confidence: true` не приводит к загрузке карточки или альтернатив.
- На стартовом экране проверены ширины 320, 390, 768, 1280 px: горизонтального переполнения и сломанных изображений нет.
- В браузере: desktop 1280×720 и mobile 390×844; старт, предпросмотр, обработка с загруженным фото, карточки Фанагории/Маркотх/Абрау, гастросочетания и альтернативы. В неполной карточке отсутствующие оценки и показатели не превращаются в 0.
- На ширине 390 и 320 px проверен портретный WebP 3072×4096: весь кадр находится внутри предпросмотра, горизонтальной прокрутки нет. «Показать целиком» открывает модальный просмотр, Escape его закрывает.
- В браузере проверены отклонение TXT и JPEG-файла свыше 15 МиБ, понятные сообщения и повторный выбор.
- Системный выбор WebP с диска проверен: фото «Зной» открылось в предпросмотре. Выбранный сценарий при смене файла не изменился.
- В браузере пройдены multiple_bottles, ambiguous_pair, no_confident_match, offline, unavailable, ratings. Переключение сценария возвращает выбранный снимок на предпросмотр.
- Переключение в реальный API не включает демо при ошибке; без backend выводится ошибка формата ответа/сервиса, доступна повторная отправка.
- Перегенерация пяти демо-карточек и изображений даёт побайтово тот же результат, включая manifest.
- Диалог камеры открывается. Реальный MediaStream встроенный браузер не предоставил; физическая съёмка остаётся проверкой на целевом устройстве, не выдаётся за завершённую. Логика capture/permission denial/stream cleanup покрыта тестами с подставным потоком.

Приложение использует кнопки/подписанные selects, видимый focus, skip-link, фокус заголовка после смены состояния, role=status/alert и нативный modal dialog с Escape. Учитывает prefers-reduced-motion. Полный аудит screen reader не проводился.

Backend доступен отдельно; автоматические проверки используют подставные HTTP-ответы и не измеряют качество модели. Перед демонстрацией на целевых устройствах остаются проверка физической камеры iOS/Android и EXIF-поворота.
